## 二、技术事实：同源度

在项目根目录跑：

```bash
python3 tools/forensics.py --suspect /path/to/对方代码 --json 取证.json
```

三个指标（脚本会逐项打印）：

| 指标 | 本项目 | 对方 | 逐字重合 | 重合率 | 判定阈值 |
|---|---|---|---|---|---|
| 专有命名（≥8 字符，排除通用词） | `<N>` | `<M>` | `<K>` | `<P>%` | > 50% 高度同源 |
| 中文长句（≥6 连续汉字） | `<N>` | `<M>` | `<K>` | `<P>%` | > 40% 高度同源 |
| 有效行（≥12 字符，归一化哈希） | `<N>` | `<M>` | `<K>` | `<P>%` | 参考项 |

**参考基线**（本项目实测，证明脚本判得出真假）：

| 对照对象 | 专有命名 | 中文长句 | 有效行 | 判定 |
|---|---|---|---|---|
| 本项目自身的全量复制 | 97.5% | 69.2% | 97.8% | 高度同源 ✓ |
| easyofd（独立实现，Python） | 8.1% | **0.0%** | 0.3% | 不构成同源 ✓ |

对方数字落在这两组之间的哪一边，结论就清楚了。**中文长句是最硬的指标**——
原创实现不可能在中文注释、提示语、文档字符串上逐字撞出几十上百条。

**取证纪律**：

- 每份证据都记**获取时间**与**获取方式**（哪个网址、什么命令）；
- 截屏要带地址栏与系统时间；
- 对方代码/安装包留存原始副本 + 计算 SHA256，不要只留截图；
- 不要剪辑、不要加标注覆盖原始内容（另存副本再加标注）。

## 六、复跑方法

任何人可以复现上面的全部数字：

```bash
# 1. 取本项目对应版本
git clone https://github.com/MrY551/xiaohuangOFD.git
cd xiaohuangOFD
git checkout <commit>

# 2. 核对原版完整性
sha256sum -c SHA256SUMS.txt
python3 -m ofdlite.buildid          # 应与发布记录一致

# 3. 取对方副本，跑同源度比对
python3 tools/forensics.py --suspect /path/to/对方代码 --json 复核.json
```

判定阈值写在 `tools/forensics.py` 文件头，不依赖主观解释。
